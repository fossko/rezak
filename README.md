# Резак

Этот репозиторий — форк проекта «Резак» Максима Ильяхова. [Оригинальный репозиторий](https://github.com/ilyahov/rezak).

Резак — браузерный редактор длинных монологов. Он вырезает паузы, оговорки, повторы, неудачные начала фраз и слова-паразиты. Вы редактируете расшифровку, а видео монтируется по тексту.

Приложение работает локально в Chrome или Edge. Видео и аудио остаются на вашем компьютере. При запуске ИИ-монтажа или подготовки текстов выбранная языковая модель получает расшифровку. Внутреннее имя пакета и формата проектов — `carver`.

## Что добавлено в форке

Ключ API для этого режима не нужен. В настройках есть ссылки для просмотра расхода и управления доступом. Вход и ИИ-операции проверены с реальной подпиской ChatGPT. [Описание интеграции](docs/feat-subscription-llm/browser-sign-in.md).
- **Защита локального сервера и рабочих пространств.** Раздача файлов ограничена папками сборки и моделей. Для проектов одного рабочего пространства действует настраиваемая квота. [Описание изменений](docs/feat-server-security/spec.md).

## Возможности

- **Импорт.** MP4 и MOV с H.264/AAC открываются через [mediabunny](https://mediabunny.dev) с чтением по требованию. Файл размером 15 ГБ можно открыть без полной загрузки в память. Для MP3, M4A/AAC, WAV, FLAC и OGG/Opus доступны расшифровка, монтаж, обработка звука и экспорт в MP3. В предпросмотре аудиофайла отображается чёрный кадр.
- **Расшифровка.** Whisper (Transformers.js на WebGPU) распознаёт русскую речь. wav2vec2 привязывает слова к записи, а их границы уточняются по звуковой волне. Пропущенные Whisper звуки показаны как `‹серые токены›`. Прогресс сохраняется каждые пять минут.
- **Монтаж по тексту.** Выделите слова и нажмите <kbd>Delete</kbd>, чтобы вырезать их. Повторное нажатие возвращает слова. Вырезанный текст остаётся видимым и зачёркнутым. Нажатие на метку паузы вырезает или возвращает её. Редактор поддерживает отмену и повтор действий и остаётся отзывчивым на расшифровках до 15 тысяч слов.
- **Паузы и звуки-паразиты.** Настраиваются порог тишины, минимальная пауза и отступы до и после речи. «Эээ», «ааа», «ммм» и «эммм» обнаруживаются по звуку, проверяются wav2vec2 и могут вырезаться автоматически. Есть три уровня чувствительности.
- **Предпросмотр и шкала времени.** На шкале видны звуковая волна, слова, вырезанные фрагменты и положение воспроизведения. Границы вырезов можно двигать мышью и клавишами. Предпросмотр точен до кадра, с плавными переходами звука на стыках. Скорость предпросмотра меняется от 0,75× до 2× без изменения высоты тона. Экспорт идёт на скорости 1×.
- **Обработка звука.** Измеритель ITU-R BS.1770 сравнивает громкость и истинный пик с целевыми значениями YouTube. Доступны компрессор, компенсационное усиление, приглушение пауз, лимитер с упреждением и выравнивание громкости по фразам.
- **Реставрация речи.** Sidon работает на WebGPU. Долю обработанного звука можно менять от 0 до 100%. Модель скачивается при первом включении.
- **Экспорт.** MP4 записывается сразу на диск через аппаратный кодировщик H.264 (WebCodecs). Для AAC применяются вырезы и плавные переходы с точностью до сэмпла. Также доступны MP3, субтитры SRT, JSON, текст с тайм-кодами и без них и XML монтажной шкалы Final Cut Pro 7. «Сохранить всё» записывает результаты в папку проекта.
- **Мат.** Детектор русского мата поддерживает пользовательские списки, подстановку `*` и регулярные выражения `/regex/`. Приглушение убирает звук и сохраняет длительность, вырезание удаляет фрагмент. Настройки приглушения для видео и MP3 могут различаться. Вырезы и итоговая длительность совпадают.
- **ИИ-монтаж.** Модель цитирует фрагменты, которые предлагает вырезать. Редактор находит их в расшифровке. Предложения можно применить сразу или проверить по одному. Поддерживаются OpenAI-совместимые API.
- **Подготовка текстов.** Исправление орфографии, структурированный текст, главы с тайм-кодами результата, тезисы, резюме, заголовок, описание и теги для YouTube, пост и фрагменты для Shorts/Reels. Шаги и запросы можно редактировать и добавлять.
- **Пакетная обработка.** Очередь автоматически расшифровывает и монтирует записи, готовит тексты и сохраняет результаты. Для каждого файла виден статус. Очередь можно остановить, продолжить или повторить сбойный шаг.
- **Совместные рабочие пространства.** Команда может работать с общими проектами через дополнительный сервис Node.js, который хранит JSON проектов. Исходники и PCM остаются на компьютерах участников.
- **Локальное хранение.** Проекты автоматически сохраняются в IndexedDB. Браузер запоминает дескрипторы исходников. После первого посещения service worker позволяет открыть редактор без интернета.

## Замеры производительности

Apple M4 Max, Chrome, ролик 1080p30 длительностью 31,6 минуты и размером 1,04 ГБ.

| Операция | Время |
|---|---|
| Открытие и извлечение звука (16 кГц) | 7 с |
| Расшифровка (Large v3 Turbo, выравнивание wav2vec2, WebGPU) | 3,5 мин (≈9× реального времени) |
| Экспорт результата длительностью 27,6 мин (H.264 1080p + AAC, на диск) | ≈1,8 мин (≈15× реального времени) |
| ИИ-монтаж с локальной моделью Ollama | ≈5 мин |
| Предпросмотр через 11 стыков за 40 с | 29,7 кадра/с, 0 запоздавших кадров |

Скрипт `tests/verify_export.py` сверяет выбранные кадры с исходником с допуском в один кадр и проверяет синхронизацию звука с допуском ±0,1 мс. Задержка кодировщика AAC измеряется и компенсируется при экспорте.

## Требования

- Chrome или Edge 113+. Для быстрой расшифровки нужен GPU с поддержкой WebGPU. При расшифровке на CPU редактор предупреждает о снижении скорости и предлагает переключиться на WebGPU.
- Node.js 20+ и npm. Разработка велась на Node 24 и 26.
- Python 3 для `npm test`. Проверка XML использует стандартную библиотеку.
- Для браузерных тестов и проверки экспорта понадобятся Google Chrome, `ffmpeg`/`ffprobe` и Python 3 с `numpy` и `Pillow`.
- Для локальных языковых моделей подойдёт [Ollama](https://ollama.com/) или другой OpenAI-совместимый сервер.

При первом запуске модели речи скачиваются и сохраняются в кэше. Large v3 Turbo занимает около 1,6 ГБ, модель реставрации — около 600 МБ.

## Быстрый старт

```bash
npm ci
npm run dev
npm run typecheck
npm test
npm run build
node serve.mjs
```

Сервер разработки с HMR доступен по адресу `http://127.0.0.1:5199`. Команда `node serve.mjs` раздаёт сборку из `dist/` по адресу `http://127.0.0.1:8123` и выставляет нужный MIME-тип для WASM. Через `file://` браузер блокирует модульные воркеры, WASM и `fetch`.

Сквозные браузерные тесты запускаются на готовой сборке.

```bash
npm run build
npx vite preview --host 127.0.0.1 --port 5200 --strictPort
node tests/e2e.mjs /path/to/video.mp4 --url=http://127.0.0.1:5200/ --steps=open,transcribe,edit
```

Тесты запускают установленный Google Chrome без окна, с флагами WebGPU. Профиль в `$TMPDIR/carver-test-profile` сохраняет скачанные модели между прогонами. Полный список тестов приведён в [руководстве по разработке](docs/DEVELOPMENT.md).

### Локальная папка моделей

При первом использовании браузер скачивает модели распознавания и сохраняет их в своём локальном кэше. Sidon загружается при первом включении реставрации.

Чтобы хранить отдельную копию моделей рядом с проектом, скачайте их заранее:

```bash
node deploy/sync-models.mjs
```

Скрипт сохраняет файлы в папку `models/` в корне проекта, рядом с `serve.mjs`. Папка исключена из Git. При запуске через `node serve.mjs` она доступна по адресу `/models/` как резервный источник, если Hugging Face недоступен. Браузер продолжает использовать свой кэш.

## Размещение

Загрузите **содержимое** `dist/`, включая скрытый файл `.htaccess` и `sw.js`, на статический хостинг.

- Отдавайте `.wasm` с MIME-типом `application/wasm`.
- Заголовки `Cross-Origin-Opener-Policy` и `Cross-Origin-Embedder-Policy` блокируют загрузку моделей с Hugging Face. Приложению изоляция источников не требуется.
- Для файлов `/assets/*` используйте неизменяемый кэш, поскольку хеши входят в имена файлов. Для `index.html` и `sw.js` включите повторную проверку при обращении.
- HTTPS нужен для service worker, запоминания дескрипторов файлов и диалога сохранения.

Пример конфигурации nginx находится в `deploy/nginx.conf.example`. Благодаря `base: './'` приложение можно разместить в подпапке. Настройка сервиса рабочих пространств, зеркала моделей и проверка перед публикацией описаны в [руководстве по развёртыванию](docs/DEPLOYMENT.md).

### Локальная модель с размещённого сайта

Укажите Ollama, с какого сайта разрешено принимать запросы.

```bash
OLLAMA_ORIGINS="https://your-site.example" ollama serve
```

В LM Studio включите CORS. Chrome может запросить разрешение на доступ HTTPS-страницы к `localhost`.

## Конфиденциальность

- Ключи API вводятся в настройках приложения и хранятся в `localStorage` браузера.
- Видео, аудио и PCM остаются на устройстве. Приложение обращается к выбранному серверу языковой модели, Hugging Face для загрузки моделей и сервису рабочих пространств, если он включён.
- Сервис рабочих пространств настраивается через переменные окружения. Исключайте из коммитов файлы `.env`, токены, пароли, адреса серверов и ссылки входа в рабочие пространства.
- Перед коммитом запускайте `npm run check:secrets`. Порядок сообщения об уязвимости или утечке описан в [SECURITY.md](SECURITY.md).

## Структура репозитория

| Каталог | Назначение |
|---|---|
| `src/lib/` | Модель данных, IndexedDB, медиа, PCM, EDL, обработка звука, громкость, функции для GPU |
| `src/transcribe/` | Whisper и wav2vec2, окна расшифровки, выравнивание, поиск звуков-паразитов |
| `src/player/` | Предпросмотр в canvas и Web Audio, изменение скорости через WSOLA |
| `src/audio/` | Обработка громкости в реальном времени (LiveMaster и DSP-воркер) |
| `src/restore/` | Sidon, подготовка входных данных, ONNX-воркер, обработка блоками |
| `src/export/` | Экспорт MP4, MP3, текста, субтитров и XML, сохранение всех результатов |
| `src/llm/` | OpenAI-совместимый клиент, ИИ-монтаж, подготовка текстов |
| `src/ui/` | Компоненты React |
| `server/` | Дополнительный сервис совместной работы с JSON проектов |
| `deploy/` | Примеры nginx и Apache, скрипты публикации и загрузки моделей на зеркало |
| `tests/` | Модульные, сервисные и сквозные браузерные тесты |
| `docs/` | Документация |

Корень репозитория — корень приложения. Сборка, зависимости, веса моделей, записи и локальные инструменты исключены из Git.
