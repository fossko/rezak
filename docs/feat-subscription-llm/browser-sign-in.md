# Следующая очередь — подключение подписки из Rezak

- Ревизия: 2
- Статус: принят для локального ChatGPT, приёмка с реальной подпиской требуется отдельно
- Контекст: [первая очередь с инструкциями](spec.md)

## Критерий готовности

Пользователь открывает «Настройки → ИИ (LLM) → Подключить подписку», выбирает поставщика и подтверждает вход в браузере. Если официальный способ использует код устройства, Rezak показывает ссылку и код текущей попытки. Затем пользователь возвращается в редактор и запускает существующую ИИ-операцию, которая успешно выполняется за счёт его подписки. На всём пути пользователю не нужен терминал или API-ключ.

Отмена, истёкший вход, отсутствие права на использование подписки и исчерпанный лимит показываются отдельными состояниями. Они не активируют другой способ оплаты. Приёмка включает браузерные тесты с подменой провайдера и отдельный успешный прогон ИИ-операции с подходящей реальной подпиской. Показывать подключение как доступное можно после прохождения этой проверки для соответствующего провайдера.

## Возможные способы

- **ChatGPT.** OpenAI указывает личные проекты, запускаемые локально, среди доступных сценариев. Пользователь подтвердил, что запускает свой проект локально. Для этого объёма используем Sign in with ChatGPT с разрешением на подписку и прямой Responses API. Публикация и сервер общего доступа остаются за рамками. [Руководство для локальных проектов](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt), [условия OpenAI](https://openai.com/policies/sign-in-with-chatgpt-terms/).
- **Claude Code.** Anthropic описывает запуск официального неизменённого Claude Code в стороннем продукте при соблюдении коммерческих условий. Одновременно условия ограничивают вход через Claude.ai в сторонних приложениях и маршрутизацию запросов от имени подписчика. Для Rezak требуется подтверждение, что весь сценарий допускается, включая вызов из настроек и выполнение операций редактора. [Условия Anthropic](https://code.claude.com/docs/en/legal-and-compliance).

## Контракты локальной реализации

- **C1.** В настройках пользователь открывает официальный браузерный вход, подтверждает использование подписки и выбирает модель из каталога аккаунта. Локальный Node-сервер на `127.0.0.1` обслуживает callback, проверяет PKCE, состояние попытки, подписанный ID-токен, совпадение аккаунта и разрешение на подписку. Пользователь не вводит API-ключ или команду.
- **C2.** Сеанс изолирован по HttpOnly-cookie. Токены живут в памяти локального процесса. После остановки сервера нужен повторный вход. Стабильный идентификатор установки хранится в локальных настройках браузера. Идентификатор регистрации повторно используется в пределах текущего процесса. Выход очищает локальный сеанс и пытается отозвать токен.
- **C3.** Выбранная модель используется существующими ИИ-операциями через локальный обработчик. Он обращается к Responses API с `store: false`, требует событие завершения и передаёт итоговый текст редактору. После истечения входа или превышения лимита пользователь видит ошибку. Режим API включается только отдельным действием пользователя.
- **C4.** Обработчик ограничен loopback, проверяет источник POST-запросов, фиксирует адреса поставщика и возвращает браузеру состояние, каталог и итоговый текст. Репозиторий и сервер рабочих пространств не получают токены. Интеграция Claude отложена.

Сервисный тест использует подписанный тестовый ID-токен и имитирует ответы OpenAI. Браузерный тест проверяет вход в интерфейсе и выполняет штатную проверку ИИ-подключения через имитацию. Приёмка с реальным аккаунтом требует подтверждения пользователем в браузере и успешной операции в редакторе.
