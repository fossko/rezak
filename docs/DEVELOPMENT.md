# Разработка

## Требования

- **Node.js 20+** и npm. Проект разрабатывался на Node 24/26, TypeScript 7 и Vite 8.
- **Python 3** для `npm test` и `tests/verify_*.py`. 52 сценария XML используют стандартную библиотеку. Для остальных проверок нужен `numpy`, а для визуального сравнения — `Pillow`.
- **ffmpeg и ffprobe** для подготовки записей и проверки экспорта.
- **Google Chrome** для браузерных тестов. Они используют установленный Chrome (`channel: 'chrome'`), запускают его без окна и с флагами WebGPU.
- **Ollama** или совместимый с OpenAI сервер для шагов `ai`, `texts`, `llmstatus` и `fasttrack`.

## Установка

```bash
npm ci
```

При `EPERM` из-за запрета записи в домашний каталог направьте кэш npm в доступное место.

```bash
export npm_config_cache="$TMPDIR/carver-npm-cache"
npm ci
```

Устанавливайте зависимости на каждой машине через `npm ci`. Нативные пакеты и дополнительные файлы ONNX зависят от платформы.

## Основные команды

```bash
npm run dev            # Vite с HMR на http://127.0.0.1:5199
npm run typecheck      # проверка типов
npm test               # модульные и сервисные тесты
npm run build          # сборка в dist/
npm run preview        # предпросмотр dist/, порт 4173 по умолчанию
node serve.mjs         # раздача dist/ на порту 8123
```

Длинные сквозные тесты запускайте на готовой сборке. HMR перезагружает страницу и прерывает тест.

```bash
npm run build
npx vite preview --host 127.0.0.1 --port 5200 --strictPort
```

`node serve.mjs` раздаёт сборку без дополнительных зависимостей с нужным MIME-типом для WASM. При открытии `dist/index.html` через `file://` браузер блокирует модульные воркеры, WASM и `fetch`.

## Тесты

### Модульные и сервисные (Node.js)

Команда `npm test` запускает модульные тесты и проверки реального `server/workspace-server.mjs` во временном каталоге. Актуальный список находится в [package.json](../package.json).

Отдельные тесты можно запускать напрямую.

```bash
node tests/profanity.test.ts
node tests/stretch.test.ts
node tests/masterchain.test.ts
node tests/xml.test.ts
```

Node.js удаляет типы при запуске `.ts`. Целевые модули `src/` должны обходиться без импортов приложения без расширения и свойств-параметров TypeScript вроде `constructor(private x…)`.

### Сквозные браузерные

```bash
npm run build
npx vite preview --host 127.0.0.1 --port 5200 --strictPort

node tests/e2e.mjs /path/to/video.mp4 --url=http://127.0.0.1:5200/ --steps=open,transcribe,edit
```

Профиль Chrome хранится в `$TMPDIR/carver-test-profile`, скриншоты — в `$TMPDIR/carver-test-out/`. Первый прогон скачивает около 2,2 ГБ моделей речи. Следующие используют кэш. Шаги выполняются в порядке определения в файле теста. [Список всех шагов](../AGENTS.md#testing).

| Шаг | Проверка |
|---|---|
| `open` | Открытие файла, извлечение звука, метаданные |
| `transcribe` | Whisper, wav2vec2, поиск звуков-паразитов |
| `edit` | Выделение слов 5–9, вырезание, отмена и повтор |
| `export` | Экспорт MP4 в OPFS, скачивание и запись `segments.json` |
| `saveall` | Сохранение всех результатов в папку |
| `mat` | Вкладка мата, пользовательские шаблоны, клавиша приглушения |
| `titles` | Вставка, обрезка и удаление заставки, составной экспорт |
| `cutedit` | Перетаскивание, подстройка клавишами, отмена и ограничение границ |
| `persist` | Сохранение правки после перезагрузки |
| `offline` | Загрузка приложения через service worker без сети |

Шагам `ai`, `texts`, `llmstatus` и `fasttrack` нужен Ollama на `http://localhost:11434` или совместимый настроенный сервер. Смена модели Ollama занимает около 14 секунд, поэтому используйте одну модель на тест.

### Численные проверки

```bash
python3 tests/verify_export.py source.mp4 "$TMPDIR/carver-test-out/export.mp4" \
  "$TMPDIR/carver-test-out/segments.json"
python3 tests/verify_mute.py all.mp4 all.mp3 mutes.json
python3 tests/verify_xml.py ...
```

`verify_export.py` сопоставляет выборку выходных кадров с исходной шкалой и измеряет задержку звука. `verify_mute.py` проверяет равную длительность и синхронизацию MP4 и MP3 с точностью до сэмпла, включая тишину в приглушённых фрагментах MP3. Для проверки синхронизации используйте численные замеры.

## Тестовые записи

Подготовьте короткий русский монолог на 1–3 минуты для `open`, `transcribe` и `edit`, запись на 20–40 минут для проверки производительности, короткую заставку для `titles` или искусственный ролик для быстрых проверок. Записи, веса моделей и скриншоты хранятся вне Git.

```bash
ffmpeg -ss 600 -t 150 -i input.mp4 -c copy "$TMPDIR/carver-clip.mp4"
ffmpeg -f lavfi -i testsrc=size=640x360:rate=30 -f lavfi -i sine=frequency=440 \
  -t 3 -c:v libx264 -pix_fmt yuv420p -c:a aac "$TMPDIR/synthetic.mp4"
```

Доступность `--url`, `--llm`, `--sens`, `--matwords` и `--range` описана в начале `tests/e2e.mjs`.

## Тестовые точки входа

- `window.__carver` — экземпляр хранилища.
- `window.__carverDebug` — `getSpeechRPC`, `pcmSlice`, `srcToOut`, `exactLevels`, `measureFile`.
- `window.__carverPlayer` — статистика воспроизведения (`drawn`, `late`, `maxGap`, `refreshes`).
- `window.__carverTestHandle`, `__carverTestDir` и `__carverNoPicker` — выбор файла и целей экспорта.
- `window.__carverTimeline` — состояние шкалы (`v0`, `span`, `W`, `drawnRev`, `draws`).
- `window.__carverChime` — настройки и журнал звукового сигнала.
- `window.__carverRestoreEp` — принудительная реставрация через `wasm` в тестах.

## Соглашения

- Интерфейс и документация для читателей — на русском. Код, комментарии и идентификаторы — на английском.
- TypeScript работает в строгом режиме. Уточняйте типы на границе Web Audio и WebCodecs вместо обхода через `any`.
- Обновляйте состояние через хранилище. Вызывайте `S.changed()` для правок или `S.bump()` для интерфейса. Перед отменяемой правкой вызывайте `S.checkpoint()`.
- Время выражается в секундах источника, а имена с `out` относятся к выходному времени. Для переходов через вырезы используйте функции преобразования шкал.
- Новое состояние слов и проектов добавляйте в снимки отмены и в перенумерацию после объединения звуков-паразитов.
- Глобальные обработчики перетаскивания находятся в `DropOverlay.tsx`. Сохраняйте `base: './'` и конфигурацию без COOP/COEP.

## CI

Конвейер в `.github/workflows/ci.yml` запускает `npm ci`, `npm run check:secrets`, `npm run typecheck`, `npm test` и `npm run build` на push и пул-реквестах. Браузерные тесты запускайте локально для релизов с изменениями редактора, экспорта или звука.

## Диагностика

| Проблема | Действие |
|---|---|
| Пустая страница из `dist/index.html` | Раздайте сборку по HTTP через `node serve.mjs`. |
| Перезагрузка или зависание e2e | Используйте готовую сборку без HMR. |
| `npm ci` выдаёт `EPERM` | Задайте доступный для записи `npm_config_cache`. |
| Модели не скачиваются | Проверьте доступ к Hugging Face и отсутствие COOP/COEP. При необходимости используйте зеркало `/models/`. |
| Тест не находит Chrome | Установите Google Chrome или задайте `CARVER_CHROME_PATH`. |
| Медленная расшифровка | Проверьте WebGPU. При переходе на CPU редактор показывает предупреждение и кнопку переключения. |
| После публикации видна старая сборка | Обновите страницу без кэша (⌘⇧R). |
| Звук рассинхронизирован после экспорта | Проверьте компенсацию задержки AAC/MP3 через `verify_export.py`. |
| Сохранение рабочего пространства даёт 401 | Проверьте `sessions.dat` и перезапуск сервиса. Клиент должен один раз обменять ссылку входа на новую сессию. |
| Сохранение даёт 504 или 503 | Проверьте лимит времени чтения запроса и таймер операции в `server/workspace-server.mjs`. |

## Добавление возможности

1. Прочитайте [AGENTS.md](../AGENTS.md) и применимый раздел [архитектуры](ARCHITECTURE.md).
2. Внесите минимальное изменение с соблюдением инвариантов.
3. Добавьте или расширьте модульный тест для чистой логики, сквозной шаг для интерфейса и экспорта.
4. Запустите `npm run check:secrets && npm run typecheck && npm test && npm run build`.
5. Для медиа и DSP выполните подходящий браузерный тест и численную проверку.
6. При изменении поведения, команды или инварианта обновите документацию.
