# Исправить две серверные уязвимости Rezak

- Идентификатор задачи: `server-security`
- Ревизия: 2
- Статус: черновик
- Принятая ревизия: —
Исходная версия: `8f7fe2f3b409c6c8cbae1c26761d42116ece52c3`

## Проблема

1. Сервер раздачи статики и Vite проверяют принадлежность файлов к разрешённой папке через строковый префикс. Для оператора это создаёт риск выдачи файлов из соседних папок с похожими именами. См. [serve.mjs](../../serve.mjs) и [vite.config.ts](../../vite.config.ts).
2. Сервер рабочих пространств при создании проекта сохраняет данные до проверки, которая действует при обновлении. Лимит размера запроса не ограничивает суммарный объём сохранённых проектов. Участник пространства может записать лишние данные и исчерпать дисковое пространство. См. [workspace-server.mjs](../../server/workspace-server.mjs) и [политику безопасности](../../SECURITY.md).

## Желаемые результаты

- **O1.** Статика и модели выдаются только из соответствующих разрешённых каталогов. Обычные URL редактора и моделей работают. Путь за границами разрешённой папки, в том числе в соседний каталог со схожим именем, отклоняется. Существующий способ подключения каталога моделей сохраняет работоспособность.
- **O2.** Создание и обновление проекта одинаково отклоняют данные с вложенным медиа. Рабочее пространство соблюдает суммарную квоту хранения. Отказ оставляет предыдущую сохранённую версию проекта читаемой и не создаёт частично сохранённых данных. Обычные проекты продолжают создаваться, обновляться и читаться.

## Ограничения

Интерфейс редактора и администрирования остаётся прежним. Рабочие документы ведём по-русски. На этапе спецификации определим правила допустимых данных, значение и единицы квоты, поведение для пространств, уже превышающих квоту, и проверки регрессий.

## Автоматические тесты

- **O1.** Проверить выдачу допустимых файлов статики и моделей, поддержку настроенного каталога моделей и отклонение путей за пределами разрешённого каталога.
- **O2.** Проверить создание и обновление допустимого проекта, отклонение вложенного медиа при обеих операциях, значения на границе квоты и сохранность данных после отказа. Проверить, что параллельные записи вместе соблюдают квоту.
